编排模式

Being 细化需求、分派任务和验收，外部 CLI Worker 执行代码。

Being 与 Worker 分别做什么

开启编排模式后，Being 负责理解目标、拆分任务、选择 Worker、判断结果和决定是否补验。代码修改、命令执行与测试交给外部 Agent CLI。该开关应用于 Desktop 中的所有会话，默认关闭。

例如提出“制作一个网页，并在桌面展示”，Being 会把实现与测试交给 Worker；Worker 完成后回传结果，Being 验收，再在原会话给出结论和预览入口。

这是调度方式的切换：没有可用 Worker 时任务会阻塞，不会自动改由 Being 执行代码。

开启前准备

  1. 连接已有 Being，并选择本机工作区。
  2. 安装至少一种受支持的 Agent CLI，并完成它自身要求的登录及权限配置。Desktop 不会自动安装 Agent。
  3. 为 Being 配置支持严格编排协议的模型入口，使用 OpenAI Responses 提供方。仅更新 Desktop 不足以启用严格模式；普通代理没有该能力时，开启会失败。

严格入口需同时能被 Desktop 与远端 Being 访问。它是独立部署的配套服务，不包含在本仓库的 Electron 安装包里。部署接口和边界见开发者说明。

开启、配置与关闭

  1. 进入 设置 → 编排模式。
  2. 开启 让 Being 专职编排。Desktop 自动检测 Agent、核验严格入口、保存设置并确认 Being 的模型地址。
  3. 确认显示“严格编排模式已开启”。如需调整，修改默认 Worker 或 CLI 绝对路径，点击“检测 Agent Kit”，再“保存模式”。
  4. 调度连接失效时，使用“重连调度工具”，并查看具体错误。

模式关闭时，下方 Worker、路径与检测等设置灰显。点击开启后又恢复灰显，表示校验或保存失败：请看设置页的错误说明，不要仅根据 CLI 显示“可执行”判断模式已经生效。

Being 或 Worker 正在执行时不能切换模式。关闭时，Desktop 仅在模型地址仍匹配原严格入口的情况下恢复先前地址；不会覆盖用户后来另行修改的配置。

优先使用设置中指定的路径，否则从 PATH 等位置检测。开启时默认 Agent 不可用但发现其他可用 Agent，会选择可用项；一个也没有则拒绝开启。实际调用仍可能因登录过期、权限、网络或提供方接口变化失败。

在会话下查看执行过程

Worker 显示在所属会话下，包含总数、执行中数量和每个任务的状态。列表可折叠。打开 Worker 可查看结果、带时间的工具调用、日志与错误；执行中可以停止。

同一工作区的 Worker 按顺序执行，避免同时修改共享文件。每次分派启动一次新的 Agent 运行，后续任务需要显式携带必要的前序结果。

状态含义
执行中CLI 仍在处理任务。
已完成CLI 正常退出并报告完成；不等于需求已经验收通过。
Heart 已接收完成通知已送达；不等于 Being 已读完结果。
验收通过 / 未通过 / 待补充验证Being 对交付及证据作出的判断。

日志有保留上限，截断会明确标注。退出码为 0 但没有提供方成功事件，仍按失败处理。

完成回调与原会话结果

Worker 结束后，Desktop 先保存结果，再通过 Heart 的回调接口通知 Being。Being 恢复原任务绑定、读取结果并验收。通知失败时重试通知，不重新执行 CLI；通知送达与验收完成分别记录。

最终结论呈现在原会话中，包含 Being 的摘要、可折叠的验收依据，以及网页产物的“打开预览”。Worker 详情用于查看执行过程。切换到另一会话不会改变结果归属。

本次修复了本地结果插入与 Loom 历史同步造成的重复追加：同一结果按稳定标识更新；可明确识别的旧重复结果在加载时合并，保留用户消息及不同任务的结果。

当 Being 空闲且验收尚未接续，Desktop 可发送明确标注的自动任务接续消息，不修改 Side by Side。提交状态不确定时不会盲目重复发送。详情页可在相应状态下“重试通知”“重新接续”或“停止接续”。

在 Desktop 内置浏览器展示

网页完成后，Being 通过展示操作提交工作区 HTML 入口或现有网页 URL，再记录验收。原会话的“打开预览”使用 Desktop 自带浏览器，无需 Worker 寻找 CLI 浏览器、iab 或外部浏览器。

静态 HTML 由 Desktop 托管；重启后可根据保留的产物重新打开，不需要重跑 Worker。动态网站仍需要可访问的后台服务，Worker 结束不保证它启动的开发服务器继续存活。

严格编排的实际边界

Desktop 只向 Being 暴露 Worker 的启动、列表、状态、等待和取消工具。配套严格模型入口还会过滤直接执行工具，并检查模型返回，确认没有越过 Worker 调度范围后才交给远端运行时。

开启模式会修改所连接 Being 的模型地址，因此也可能影响该 Being 在其他入口的会话。每次 Desktop 发送消息或分派任务前会再次核验；模型入口变化或调度连接不可用时阻止执行。

这不是远端运行时的全局权限管理：不会撤销独立后台任务、停止其他入口已启动的任务，也不能阻止管理员更改模型配置。严格入口可能在整段响应检查完毕后才显示 Being 文本；Worker 事件仍持续更新。

CLI 使用自身的权限配置。选择工作区不代表所有外部 CLI 都被相同的系统沙箱隔离；具体能力取决于对应适配器和 CLI。

常见问题与尚未支持的能力

  • 开启后又关闭：依次检查工作区、CLI 检测与登录、OpenAI Responses 配置、严格入口能力及其可达性。
  • Worker 完成但 Being 没回复：分别看执行、通知和验收状态；已有 Worker 结果保留，优先恢复通知或接续。
  • 模型接口报 HTTP 500 等错误：Being 当前回复可能中断，已启动 Worker 不因此自动重跑；需另查代理及模型服务。
  • Worker 内再启动 Codex 失败：外层 Worker 的沙箱、代理、登录与证书环境可能与宿主不同。本次牌局验证通过宿主运行解决了调用问题，但宿主接续尚未成为 Desktop 通用自动托管功能。不要以关闭 TLS 校验或删除沙箱标记代替正确接入。
  • 退出与重启：切换 Desktop 会话或关闭到托盘保留执行；退出、断开连接或切换 Being 会停止 Worker。重启后原执行中记录标为中断，不自动重放。

Cursor SDK、任意 Agent SDK、跨任务通用宿主子进程接续均不属于当前承诺的能力。下载附件、版本与平台以 Releases 实际发布内容为准。
