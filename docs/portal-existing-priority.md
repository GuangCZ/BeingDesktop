# 已部署 Portal 优先

Desktop 先识别已有 Portal 进程与配置，再决定是否需要部署。已有部署保留工作区、配置、身份、凭据和原服务管理器；识别到可靠的管理接口后，Desktop 可调用原管理器启停及更新。即使进程暂时退出，也不会创建重复部署。自动拉起仍只用于 Desktop 托管的实例。

## 工作区归属

- `settings.workspace` 继续用于 Desktop 的项目、文件浏览和终端。
- `settings.portalWorkspace` 只记录新建 Portal 的待选目录。
- 已托管 Portal 使用 `managedPortal.workspace`，项目切换不改变此值。
- 外部 Portal 的页面展示只读配置工作区；无法确认时显示未知，不回退到 Desktop 项目目录。
- 保存 Portal 部署不再修改 Desktop 项目目录。新机器缺少 Portal 时，仍可创建独立的默认 Portal 工作区。

## 已有部署识别与边界

只读检查运行程序旁的常规 `portal.toml`、选定的非托管配置，以及用户目录下 `.heart-portal/portal.toml`。配置只提取顶层 `workspace` 和 `name`；不输出令牌或其他配置内容。不可读、符号链接、重复字段和无法解析的配置保留已有部署的优先权，但不猜测工作区。

配置位置和名称是配置元数据，不证明运行进程采用了该文件，也不证明该 Portal 已连入当前 Being。自定义启动参数可能指定其他配置；无法建立对应关系时，需要核对原部署。消息环境不再把所有本机 Portal 写死为 `being-desktop`，工具调用仍需核对实际绑定。

macOS 已有部署必须匹配原 LaunchAgent 的程序、配置、启动脚本及 PID；Windows 必须匹配官方 0.8.3+ 守护的保存配置和 PID。匹配后，在设置 → 本机 Portal → 已有 Portal 卡片点击“一键接管”。接管只保存绑定记录，不重启进程，也不改原配置；成功显示“已接管”并开放启停与更新。接管记录跨 Desktop 重启保留，原服务或启动脚本改变后需重新接管。启停仍走原服务管理器。未知启动脚本、手动进程和无法确认的实例继续只读显示。外部部署停止时，界面明确显示“已有部署（未运行）”。

## 两种更新方式

- 已有部署：原位替换程序，保留原配置、身份、凭据、工作区和 kits。macOS 只在原 LaunchAgent 增加 `HEART_PORTAL_SUPERVISED=1`，避免新版再启动第二个守护；更新前备份原 plist，失败恢复。官方运行目录之外的程序暂不原位更新，避免上游自动迁移改变部署。
- Desktop 部署：程序独立安装在 `~/.heart-portal/desktop-runtime/v<version>-<platform>-<arch>/`，更新时切换托管版本路径，无需重新打包 Desktop。配置和工作区继续使用原位置。

默认发布包为 0.8.3。启动及每 6 小时检查官方稳定版；兼容范围内的更新可在后台下载。每次版本请求最多等待 10 秒，短暂网络故障或服务端 5xx 会自动重试一次；GitHub 限流则遵守重试时间。检查失败保留上次成功结果和时间，但不据此宣称当前仍是最新版。每个资产必须有官方 SHA-256 和大小，下载后核验，macOS 另验代码签名。当前兼容范围为 0.8.x、补丁版本至少为 3；跨版本线需更新 Desktop 后重新验证。

下载不停止 Portal。上游没有可靠的全局任务排空接口，所以运行中的主程序不会根据静默日志或 Desktop 聊天状态自动重启。点击“停止并更新”才执行停止、替换、启动与验证；执行中的工具调用可能中断，应待任务结束后操作。停止的实例可直接替换。

更新事务位于 Desktop 用户数据目录的 `portal-updates/`，保留旧程序、原 plist（如适用）、Windows 守护脚本（如适用）和结果记录。失败自动回滚；若恢复无法确认，保留事务并显示“恢复”，不重放消息或工具调用。重启后的验证要求新进程稳定、版本一致、新日志中的 relay 握手和本地工具注册；这不等同于 Being 发起的端到端工具调用。

## 工具包热重载

Portal 0.8.3 自动扫描 kits 变更（约 5 秒），也提供 `portal_kits_reload` 主动重载代码、依赖和凭据，并通知工具列表变化；进行中的调用继续由旧 kit 进程完成。`portal_tools_reload` 用于自定义工具。以上无需重启 Portal 主进程；主程序升级和配置/权限修改仍需受控重启。

## 验证

2026-09-09 源码验证：1101 项单元测试通过，1 项跳过；Portal 设置界面 50 项检查、Town 界面 85 项检查通过，语法检查通过。包含外部进程退出、配置暂时消失、项目切换、配置字段歧义和停止状态下禁止重复部署的回归案例。

上述 2026-09-09 数据为旧版回归基线。更新机制的验证另覆盖事务失败回滚、中断恢复、原管理器身份匹配、下载取消和真实 0.8.3 kit 热重载；Windows 管理器使用隔离夹具验证，尚无真实 Windows 运行验收。

## 已接管 Portal 的权限

接管后，权限页直接读取原配置的 `[tools]` 六个布尔开关；缺省值按 Portal 0.8.3 的默认值处理。保存只修改对应布尔值，保留身份、凭据、工作区、kits、其他字段和注释。读取与保存之间配置已改变时拒绝覆盖。运行中的实例通过原管理器停止、保存和启动；失败时恢复原配置并尝试验证原服务恢复。每次实际修改在配置旁保留权限备份，无更改的保存不写文件、不重启。
