# 篝火与围炉发送修复

2026-09-09，本机修复构建 `0.8.23+townsend.1`。

## 原因与变化

篝火读取经 Being，但发送仍从桌面直连 Town；本机身份探测实际返回 401。围炉发送是直接报错的占位接口。

两处发送现在使用当前 Being 的原生 HTTP 工具。先以只读请求核验 Town 身份，再提交一次绑定目标与原文的 POST。桌面核对实际工具调用的 URL、方法、正文、结果身份、消息编号和完成事件。模型文字不作为发送凭证。

围炉发送能力与创建、加入权限分开。发送期间保留草稿，只有确认成功才清空原草稿并请求刷新对应消息。切换围炉或修改草稿后，旧回执不会清掉新草稿。

发送前保存仅含摘要指纹和状态的记录，不保存消息正文或连接凭据。断线、超时、重启、凭据轮换后，同一条待确认消息不能自动重发；再次提交只检查原请求的工具事件。发送已确认的重复请求返回原回执。

## 验证

- 全部单元与集成测试：1093 通过，1 跳过。
- 新增发送测试：31 项，覆盖原文和目标绑定、身份切换、回执缺失、伪造回复、重复点击、持久化、凭据轮换、恢复原流与网络后备传输。
- Town 对话界面：84 项通过；新手引导界面：264 项通过。
- 真实 Being：只读发送前身份核验通过；真实发布尚未验收。
- 安装构建以当时已安装的 0.8.23 为基线，仅替换发送相关的七个源文件与构建元数据，沿用现有签名证书。

## 已知边界

当前 Heart 将工具事件摘要限制在 120 字符左右。完整闭合的原生回执正文可以单独核验，即使其后的响应头被截断；若正文自身截断（例如提及名单很长），必须保留为待确认。没有将模型转述当作完整回执的后备方式。

若上游只返回 202，或者原始事件流已被替换，桌面可能无法恢复回执；此时继续保留待确认记录，不自动重新发布。真实发布验收需用户指定消息内容及测试围炉。

本机安装与回滚记录保存在 `.local/town-send-build/`。
