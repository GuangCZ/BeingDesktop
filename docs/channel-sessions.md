# Channel 独立会话

Desktop 发起飞书、微信的连接和状态检查时，分别创建「飞书 · Channel」「微信 · Channel」会话。创建发生在首次请求发送前，不改变当前打开的会话或草稿。

每个 Being、Desktop 和 channel 对应一个稳定的会话 ID。同一渠道的后续请求以及在该会话中继续提问，使用同一个 `scene_id`；重启后保持关联，重命名不改变关联。切换 Being 后使用另一组会话。

渠道请求从第一条起携带 `scene_id`、`scene_meta` 和请求关联 ID，不再依赖旧的服务端 `session_id`。回复必须属于该 scene，并且通过原有请求 ID、Being、route、channel 校验，才能更新渠道状态。202 或中断后不重发操作，后续状态检查复用同一 scene。

操作结束后，Desktop 只读同步历史和未结束的回复流。服务端带有该 scene 的记录进入对应渠道会话，其他桌面对话保持各自归属。

## 已有绑定状态

打开消息渠道、切换渠道或刷新页面只读查询已有绑定，不创建会话、不发送 Being 消息、不重新登记渠道。兼容服务端 `ready` 布尔字段：就绪显示已连接，尚未就绪的已有记录显示已登记。已连接时不再显示连接向导或新建连接按钮。

Desktop 无权读取 IP Trust 接口、请求失败或结果不明确时，显示未能确认状态，不判定未绑定；已有确认结果保留并说明无法取得最新状态。只有用户点击「请 Being 核对绑定状态」才通过对应渠道会话发起只读核对任务。

## 边界

这是 Desktop 到 Being 的渠道功能通信及其回复归属。它不修改飞书、微信服务端的入站适配器，也不会把一条普通桌面回复自动发送到外部平台。外部平台主动推送的消息，仍需要上游提供可识别的来源和 scene；无来源的旧记录不能可靠地补分到某一渠道。本次只读检查中没有取得带渠道来源标记的入站样本，未进行真实外部平台收发验证。

会话用于区分记录和通信归属，Being 的记忆仍然共享。
